# SBI Trade Import Specification

## 目的

SBI証券の約定履歴CSVを非公開領域からSQLiteへ安全かつ再現可能に取り込み、
売買履歴の統計分析とSado Frameworkの検証に利用する。

## 入力

- SBI証券「約定履歴照会」のCSV
- 文字コードはCP932またはUTF-8
- 検索条件や注記を含む場合、`約定日`と`銘柄`を持つ明細ヘッダーを自動検出する
- 銘柄コードは英字を含み得るため文字列として保存する
- 元CSVは`data/private/`に置き、Gitへ登録しない

## SQLite

`executions`、`closed_trades`、`unmatched_executions`を作成する。約定の正規化値と
同一内容の出現順からSHA-256指紋を生成し、同じCSVの再取込を冪等にする。同一CSV内の
同内容約定は別約定として保持する。

## 対応付け

現物・信用買建は買いから売り、信用売建は売りから返済買へFIFOで対応付ける。
部分決済は数量単位で分割する。取得期間外の建玉や期間末の未決済建玉は
`unmatched_executions`へ理由付きで残す。

## 損益

SBI CSVの`受渡金額/決済損益`にある信用決済損益を確定損益の正とする。FIFOによる
価格差損益は保有期間や売買傾向の推定用である。建玉指定、株式分割、手数料・諸経費の
扱いにより両者は一致しない場合がある。

## 出力と安全性

生成DBは`data/database/`、レポートは`data/generated/`へ保存し、いずれもGit管理外と
する。公開可能なのはスクリプト、仕様、匿名化した検証結果、テストのみとする。

# Trade Episode・公開集計の追加仕様

## Trade Episode

約定単位やFIFO決済ロットとは別に、同一銘柄・口座区分・売買方向の建玉が
ゼロから始まり、再びゼロになるまでを一つの `trade_episodes` レコードへ
集約する。

- 現物と信用を混在させない
- LONGとSHORTを混在させない
- 分割買い、買い増し、部分決済を同一エピソードに含める
- 未決済は `OPEN`、全決済は `CLOSED` とする
- 確定統計には `CLOSED` だけを使用する
- 同じ元データから再生成した場合、`episode_key` と整数IDを維持する

`episode_key` は銘柄識別子、口座、現物・信用、売買方向、最初の約定IDから
決定的に生成する。これにより、再実行時も既存行を更新できる。

## 数値計算

既存DBとの互換性のため、SQLite列は `REAL` を維持する。Trade Episodeの
集約処理では、DB値を文字列経由で `Decimal` に変換して計算し、保存時だけ
数値へ戻す。数量比較には小さな許容誤差を設ける。

## 公開用データ

公開JSONは許可した集計項目だけから新しく組み立てる。DB行や個別取引を
そのまま匿名化する方式は採用しない。

公開しない項目:

- 銘柄名、証券コード、口座名
- 約定ID、エピソードキー
- 価格、数量、個別取引
- 実損益額、資産額

公開可能な項目:

- 取引数、勝率、PF、ペイオフレシオ
- 金額を含まない期待値指数
- 保有日数、連勝・連敗
- 保有期間、曜日、売買方向、現物・信用の集計
- 集中度

実データから生成するJSONは `data/generated/public/` に保存し、Git管理対象外と
する。GitHub Actionsでは `.github/pages/fixtures/` の完全匿名サンプルを使う。
